# Jenkins CI Notes

## Why Jenkins exists

Jenkins is the automation engine that orchestrates the software delivery pipeline from source checkout to deployment readiness.

## Pipeline flow

Checkout -> Compile -> Unit Test -> Package -> SonarQube -> Quality Gate -> Docker Build -> Trivy -> Registry -> Deploy

## Important concepts

- Controller: the central Jenkins server that manages jobs, agents, and pipeline configuration
- Agent: the worker node that executes the build steps
- Workspace: the checked-out repository on the agent filesystem
- Executor: a slot for running a build task
- Credential: securely stored token or username/password for integration with GitHub, Docker, SonarQube, or Nexus
- Stage: each major step in the pipeline
- Post: actions that run after the pipeline completes, such as archiving artifacts or sending notifications
- Artifact: file generated by the build, usually a JAR or WAR
- Parameter: runtime input such as environment name or deployment type

## Senior interview answer

A strong Jenkins answer explains that the pipeline enforces repeatability, traceability, and quality gates. It makes the build process consistent across environments and turns delivery into an auditable workflow instead of an ad hoc manual process.

## Project usage

This project uses Jenkins to build the Java service, run tests, push quality gating through SonarQube, secure the image through Trivy, and prepare deployment to a target environment.
